# 보안 및 대응 정책

## 현재 대응 수준

W10의 `DryRunResponseService`는 계속 실제 변경 없이 `executed=False`를 반환한다. W11의 `ActualResponseService`는 dry-run 통과, 사용자 승인과 실행 직전 대상 재검증을 모두 통과한 명령만 별도 실행한다.

## 기본 안전 경계

- 허용된 대응 종류만 명령 스키마로 생성할 수 있다.
- 명령의 사건 ID와 검증된 보고서의 사건 ID가 같아야 한다.
- 보고서의 `recommended_actions`에 없는 조치는 차단한다.
- 프로세스는 PID만 사용하지 않고 시작 시각과 이미지 경로를 함께 요구한다.
- 격리 대상은 전체 파일 경로와 SHA-256을 함께 요구한다.
- 증거 추가 수집은 보고서에 포함된 원본 이벤트 ID만 요청할 수 있다.
- 시스템 핵심 프로세스와 보호 경로는 사용자 승인 여부와 관계없이 차단한다.
- 종료와 격리는 명령별 사용자 승인을 요구하며 승인은 기본 10분 후 만료된다.
- 차단된 dry-run에는 승인 요청을 만들 수 없다.

기본 정책은 `config/response-policy.json`에서 관리한다. 보호 목록을 줄이거나 승인 요구를 해제하는 변경은 보안 회귀 테스트와 사용자 검토 없이 적용하지 않는다.

## 실제 대응 구현 상태

실제 대응 실행기는 다음 조건을 적용한다.

1. 실행 직전에 PID·시작 시각·경로·해시를 다시 조회해 명령 대상과 비교한다.
2. 승인 레코드가 같은 명령 ID에 속하고 만료되지 않았는지 확인한다.
3. 파일 격리는 영구 삭제 대신 접근이 제한된 저장소로 이동하고 복원 메타데이터를 남긴다.
4. 방화벽 변경과 파일 이동은 반대 작업으로 복구할 수 있어야 한다.
5. 요청, 검증, 승인, 실행, 실패와 복구 결과를 감사 로그에 남긴다.
6. 일부 단계가 실패하면 무한 자동 재시도하지 않고 제한된 재시도 후 사용자 검토로 전환한다.
7. 프로세스 종료는 전체 하위 트리를 먼저 조사하고 보호 프로세스가 하나라도 포함되면 명령 전체를 거부한다.
8. 플레이북은 묶음 승인으로 우회하지 않고 실제 시스템 변경 명령마다 별도 승인을 요구한다.
9. 격리·네트워크 차단 복구 정보와 차단 만료 시각은 재시작 후에도 유지한다.

감사 로그는 각 레코드에 직전 레코드 SHA-256을 포함해 순서 변경이나 내용 변조를 검사할 수 있다. 방화벽 변경은 관리자 권한이 필요하며 권한 부족을 우회하지 않고 실패로 기록한다.

## 로컬 API 경계

- 기본 네트워크 바인딩은 `127.0.0.1`이며 요청 클라이언트도 loopback인지 확인한다.
- `Host`는 localhost·127.0.0.1·::1만 허용하고 쿠키로 인증한 변경 요청의 `Origin`은 현재 포트와 정확히 같아야 한다.
- 상태·사건·대응 API는 최소 32자 Bearer 토큰을 상수 시간 비교로 검증한다.
- 토큰은 설정 파일이나 Markdown에 저장하지 않고 `WEAVEXDR_API_TOKEN` 환경 변수로 전달한다.
- 브라우저는 API 토큰을 프로세스별 임의 세션 값으로 교환하고 HttpOnly·SameSite=Strict 쿠키만 보관한다. 서버 재시작과 정상 종료 시 이전 브라우저 세션은 무효화된다.
- 실제 대응 서비스가 명시적으로 구성되지 않은 API 프로세스는 실행·복원 요청을 `503`으로 거부한다.
- API 입력은 기존 Pydantic 대응 명령 스키마와 사건별 권고·보호 정책을 다시 통과한다.
- 모든 응답은 frame 포함을 차단하고 CSP·MIME 추측 방지·referrer 차단 헤더를 제공한다.
- 단일 인스턴스 다시 열기는 평문 비밀을 파일에 쓰지 않는다. 사용자 범위 DPAPI로 보호한 비밀을 이용해 15초 유효 타임스탬프·일회용 nonce·HMAC-SHA256을 검증하고 재사용 nonce를 거부한다.

## 지식 그래프 개인정보와 보존

- 사용자 이름 원문은 저장하지 않고 설치별 salt를 이용한 단방향 가명 식별자로 바꾼다.
- 사건 보존 기간이 지나면 사건 전용 엣지와 연결 정보를 지우고, 어떤 보존 사건에서도 참조하지 않는 노드만 함께 삭제한다.
- 공유 엔티티는 다른 보존 사건의 증거를 훼손하지 않도록 해당 사건이 남아 있는 동안 유지한다.
- 실제 설치에서는 기본 문자열이 아닌 설치별 `privacy_salt`를 비밀 저장소에서 주입해야 한다.

## 최소 권한 경계

- 분석, 저장, 로컬 API와 화면은 일반 사용자 프로세스로 실행한다.
- 포터블 Sysmon 수집 권한은 채널 SDDL에 현재 사용자 읽기 `0x1`만 추가하며 기존 값을 백업하고 복원 절차를 제공한다.
- 대시보드 자동 설정은 인증된 loopback API에서 사용자가 버튼을 누른 경우에만 `runas` UAC를 시작한다. UAC를 우회하지 않으며 API 토큰과 사용자 입력을 상승 프로세스 명령행에 전달하지 않는다.
- 실제 대응 기능은 명시적 기능 스위치가 없으면 비활성화한다.
- 데스크톱의 실제 대응 기능 스위치는 `WEAVEXDR_ENABLE_ACTIVE_RESPONSE=1`이며 일반 실행 기본값은 비활성이다.
- 프로세스 종료와 파일 격리는 기존 대상 재검증·승인 정책 안에서 수행한다.
- 방화벽 변경과 서비스 설치·제거는 관리자 권한이 확인된 별도 작업 경계에서만 허용한다.
- 권한 부족은 우회하지 않고 실패 및 감사 이벤트로 반환한다.
- `%LOCALAPPDATA%\WeaveXDR`의 보호 DACL은 현재 사용자와 LocalSystem만 전체 접근할 수 있게 하고 새 DB·로그·격리·세션 파일에 상속한다.
