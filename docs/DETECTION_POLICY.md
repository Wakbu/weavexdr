# 탐지 기준 및 위협 정보 정책

WeaveXDR은 한 기관의 목록만 악성 판단 기준으로 사용하지 않는다. OWASP는 웹·애플리케이션 및 AI 시스템 위험을 다루는 기준으로 사용하고, 악성코드·웜·랜섬웨어와 Windows 엔드포인트 행위는 MITRE ATT&CK, Microsoft Defender, YARA와 CISA 자료를 함께 사용한다.

## 기준 출처와 역할

| 출처 | 적용 범위 | 프로젝트 내 역할 |
|---|---|---|
| OWASP Top 10 최신판 | 웹·애플리케이션 공격과 설계 위험 | 네트워크·애플리케이션 이벤트 규칙 및 향후 API 보안 검증 |
| OWASP GenAI Security 최신판 | 프롬프트 인젝션, 과도한 에이전트 권한, 출력 검증 등 | AI 분석 노드와 도구 호출의 보안 정책 |
| MITRE ATT&CK Enterprise | 실행, 지속성, 권한 상승, 방어 회피, 자격 증명 접근, 전파 등 공격자 행위 | 행위 기반 탐지 규칙의 기본 분류 체계와 근거 ID |
| Microsoft Defender 및 YARA | 알려진 악성 파일, 바이러스, 트로이목마, 웜, 랜섬웨어와 의심 코드 패턴 | 파일 검사와 악성코드 판정 근거 |
| CISA KEV | 실제 공격에 사용된 취약점 | 설치 소프트웨어·취약점 위험의 우선순위 보강 |

OWASP 항목은 악성코드 종류나 엔드포인트 행위를 직접 열거하는 데이터베이스가 아니므로 단독 기준으로 사용하지 않는다. 반대로 알려진 해시나 서명만으로도 변종과 새로운 공격을 놓칠 수 있으므로 MITRE ATT&CK 기반 행위 규칙과 로컬 이상 징후를 병행한다.

## 추가 행위 탐지 원칙

다음처럼 특정 악성코드명이 없어도 공격 가능성이 높은 행위를 탐지 대상으로 삼는다.

- Office 프로그램이 스크립트 인터프리터나 시스템 관리 도구를 실행
- 인코딩·난독화된 명령, 메모리 실행 또는 다운로드 후 즉시 실행
- 시작 프로그램, 서비스, 예약 작업 등 비정상적인 지속성 등록
- 보안 도구 중지, 로그 삭제, 검사 제외 경로 추가와 같은 방어 회피
- 짧은 시간의 대량 파일 변경·암호화·확장자 변경
- 다수 호스트나 공유 폴더로 빠르게 복제되는 웜 형태의 전파
- 비정상적인 자격 증명 접근, 권한 상승, 원격 실행과 횡적 이동
- 평소와 다른 외부 연결, 반복 비콘, 대량 전송 또는 알려지지 않은 실행 파일의 통신

이상 징후 하나만으로 악성이라고 확정하지 않는다. 파일·프로세스·네트워크·시간·사용자 맥락을 결합하고, 규칙 ID와 원본 이벤트를 근거로 남긴 뒤 위험 점수와 독립 검증 노드를 통과시킨다. 시스템 변경이나 격리는 별도의 대응 안전 정책과 사용자 승인 규칙을 따른다.

## 최신 기준 갱신 정책

- 각 규칙에 `source`, 외부 기준 ID, 기준 버전, 갱신 시각과 로컬 규칙 버전을 기록한다.
- 외부 기준은 HTTPS 공식 출처에서만 가져오며 다운로드 실패 시 마지막 검증본을 유지한다.
- 새 규칙은 바로 자동 대응에 사용하지 않고 스키마 검사, 중복 검사, 정상·의심 회귀 테스트를 통과한 뒤 활성화한다.
- 규칙 갱신으로 오탐이나 오류가 늘면 직전 검증본으로 되돌릴 수 있게 버전을 보관한다.
- 외부 문서의 설명은 탐지 근거일 뿐 AI 모델이 임의의 명령을 실행하도록 하는 입력으로 사용하지 않는다.

## 구현 배치

- `W8 탐지 상관분석`: 규칙 설정 스키마, OWASP·MITRE ATT&CK·CISA 매핑, 행위 규칙과 점수 정책 구현
- `W9 오탐 관리`: 출처별 증거 추적, 허용 목록과 사용자 피드백 반영
- `W14 지식 그래프`: 사건·이벤트·ATT&CK 기법·OWASP 범주·취약점 관계 저장 및 조회
- `W16 품질·보안`: 규칙 갱신 검증, 회귀·오탐·성능 시험과 안전한 롤백 검증

## 현재 구현 상태

`W8 탐지 상관분석`에서 다음 기반을 구현했다.

- `config/detection-rules.json`: 외부 기준 버전, 규칙 조건, 심각도와 참조 ID
- `RuleBundleManager`: 스키마·중복·HTTPS 출처·선택적 SHA-256 검증, 활성본 교체와 롤백
- `config/risk-policy.json`: 모델과 분리된 점수 상한, 판정 임계값과 허용 대응안
- `EventCorrelationEngine`: 기본 5분 시간 범위, ProcessGuid 또는 PID·시작 시각 기반 연결
- `AttackChain`: 부모·자식 프로세스와 파일·네트워크 원본 이벤트 ID 보존

외부 기준을 자동 다운로드하는 기능은 아직 활성화하지 않았다. 향후 갱신 작업은 후보 파일을 별도로 내려받아 검증·회귀 테스트한 후 활성화하며, 실패 시 마지막 검증본을 유지한다.

`W9 오탐 관리`에서 보고서에 판정 Finding, 제외된 Finding, 공격 흐름과 원본 정규화 이벤트를 함께 저장하도록 확장했다. 정상 행위 예외는 규칙 ID만으로 만들 수 없고 구체적인 이벤트 선택자, 검토자 승인과 만료 시각이 필요하다. 오탐 피드백은 SQLite에 보존하며 서로 다른 사건에서 반복 확인된 경우에만 허용 목록과 회귀 평가 데이터 후보를 만든다. 후보 적용도 명시적 재확인을 요구한다.
