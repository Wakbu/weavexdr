# WeaveXDR 아키텍처

## 데스크톱 인스턴스 경계

데스크톱 런타임은 사용자 범위 Windows 명명 뮤텍스로 소유권을 결정한다. 소유 인스턴스는 PID·loopback 포트·버전·프로세스 전용 난수를 원자적으로 교체해 기록한다. 두 번째 실행은 난수로 보호된 loopback 재열기 API를 호출하고 응답의 PID·버전이 같을 때만 종료한다. 이는 다른 프로그램의 loopback 서버를 WeaveXDR로 오인하는 것을 막는다.

## 실시간 보안 이벤트 경로

`SysmonCollector`는 Windows Event Log API에서 현재 마지막 레코드 이후의 이벤트 ID 1·3·11만 폴링한다. 원본 XML은 `SysmonXmlParser`에서 공통 이벤트로 정규화되고 ProcessGuid 기반 사건 ID로 묶인 뒤 `PersistentIngestionService`를 통해 중복 제거·SQLite 저장·실행 그래프 분석·대시보드 알림으로 전달된다.

포터블 EXE는 일반 사용자 수집기를 함께 시작하고 종료 시 작업 스레드를 먼저 정리한다. 권한이 부족하면 인증된 대시보드 요청이 Windows UAC를 열고, 내장 스크립트가 현재 사용자에게 Sysmon 채널 읽기 `0x1`만 추가한다. 설치형 Windows 서비스는 LocalSystem 컨텍스트에서 동일 수집기를 사용한다. 로그 누락·권한 부족·모듈 오류는 서버를 중단하지 않고 상태 API에 표시하며 자동 재시도한다.

## 대응 자동화와 복구

실제 대응기는 실행 전 프로세스 하위 트리와 보호 대상을 다시 조회하고, 자식 프로세스부터 종료한다. 네트워크 차단은 IP·도메인·프로그램 경로를 구분하고 만료 시각을 기록한다. 격리와 네트워크 차단의 복구 메타데이터는 SQLite에 남아 앱 재시작 뒤에도 승인형 되돌리기와 기간 만료 해제가 가능하다.

`ResponsePlaybookService`는 명령을 순차 실행하며 각 단계의 의존성, 별도 승인과 실패 후 진행 여부를 적용한다. 시뮬레이션은 영향 범위와 보호 대상만 계산하고 시스템을 변경하지 않는다. 데스크톱은 `WEAVEXDR_ENABLE_ACTIVE_RESPONSE=1`을 명시한 경우에만 실제 실행기와 플레이북을 연결한다.

## 저장소 수명 주기

`DatabaseLifecycleManager`는 DB 무결성·크기·여유 공간·스키마 버전을 보고하고 SELECT 쿼리 계획을 점검한다. 백업은 SQLite backup API로 임시 파일을 만든 뒤 무결성 검사와 원자적 교체를 거친다. 복원은 지정 백업 폴더의 직접 자식만 허용하고 기존 DB 롤백 사본을 남긴다. 스키마 변경은 버전별 트랜잭션으로 적용하며 실패 시 해당 변경을 롤백한다.

보존 기간이 지난 사건·이벤트·배치는 삭제 전에 gzip JSON 증적 묶음으로 내보낼 수 있다. 실행 중인 SQLite 파일은 직접 교체하지 않고 검증된 복원 후보를 예약한 뒤 다음 일반 실행에서 DB 연결보다 먼저 적용한다. 이벤트 버퍼는 기본적으로 초과 입력을 거부하며, 명시적 샘플링 모드에서는 DNS·방화벽 반복 이벤트만 균등 샘플링하고 프로세스·파일·Defender·계정 이벤트는 보존한다.

빠른 파일 검사는 경로 열거를 백그라운드에서 수행하고 최근 위험 형식을 최대 8개 작업자로 분석한다. YARA·해시·형식 분석은 파일 단위로 수행하지만 PowerShell Authenticode는 빠른 프로필에서 생략하고 Defender 사용자 지정 검사는 파일마다 실행하지 않고 요청 루트별 한 번만 병행한다. 실시간 단일 파일 감시는 기존 전체 검사 경로를 유지한다.

`RuntimeRecoveryManager`는 DB 연결 전에 이전 실행 마커를 확인한다. 비정상 종료 흔적이
있으면 SQLite 무결성을 검사하고 정상 DB의 검증 백업을 만든다. DB가 손상됐고 검증된
롤백이 있으면 손상본을 별도 보존한 뒤 롤백을 적용하며, 둘 다 없으면 자동 시작을
중단한다. 정상 종료 시에만 실행 마커를 제거한다.

`RuntimeHealthMonitor`는 전원·배터리와 장시간 샘플 공백을 기록한다. 배터리 30% 이하
저전력 모드에서는 실시간 Windows 이벤트 수집을 유지하고 디렉터리 파일 폴링만
2초에서 8초로 늦춰 탐지 공백과 배터리 소모 사이의 경계를 분리한다.

## 조사 시각화

대시보드는 사건의 `Host → Process → File/IP` 관계를 SVG 엔티티 그래프로 표현한다. Sysmon 네트워크 이벤트는 소스·목적지 주소와 연결 방향을 보존하여 인바운드와 아웃바운드를 구분한다. IP 지도는 현재 로컬 추정 데이터만 사용하며, 확인되지 않은 주소를 임의의 국가로 단정하지 않고 GeoIP 데이터 연동 필요 상태로 표시한다.

개요의 3D 지구본은 번들된 Natural Earth 국가 경계 SVG를 오프스크린 텍스처로 만든
뒤 역방향 구면 투영하여 외부 CDN이나 WebGL 라이브러리 없이 회전·확대한다. 최근
고위험·검토 필요 사건의 확인된 GeoIP만 빈도 마커로 겹쳐 표시한다.

시각 체계와 반응형 검증 기준은 [UI_DESIGN.md](UI_DESIGN.md)를 따른다.

사건 화면은 `/incidents`의 서버 측 `limit·offset·query·verdict` 처리와 `/incidents/stats`의 정확한 전체·필터 통계를 분리한다. 따라서 목록 페이지 크기나 기본 100건 제한이 전체 사건 KPI로 오인되지 않는다. 실시간 이벤트는 짧게 묶어 이 두 데이터 집합과 관련 화면만 갱신한다.

## 보안 지식 그래프

실행 그래프는 현재 사건을 분석하는 작업 흐름이고, 보안 지식 그래프는 여러 사건에서 반복되는 대상과 관계를 장기 조회하는 저장 구조다. 두 그래프는 서로 대체하지 않는다.

현재 백엔드는 별도 서버가 필요 없는 SQLite 속성 그래프다. `Host`, `User`, `Process`, `File`, `IP`, `Alert` 노드와 `RUNS`, `EXECUTES`, `SPAWNED`, `CREATED`, `CONNECTED_TO`, `OBSERVED` 관계를 저장한다. 사용자 이름은 원문 대신 로컬 salt로 만든 단방향 식별자만 저장한다.

사건 보고서 변환 파이프라인은 다음 기능을 제공한다.

- 동일 엔티티가 겹치는 과거 유사 사건 순위 조회
- 제한된 hop 수의 공격 경로 조회
- 같은 프로세스의 파일 생성과 공인 IP 연결을 묶는 그래프 탐지
- 노드·엣지·DB 크기 측정과 저장 백엔드 재평가

개인용 단일 호스트 환경에서는 운영과 복구가 단순한 SQLite를 유지한다. 기본 기준인 노드 100만 개 이상 또는 실제 조회 지연이 허용 범위를 넘을 때만 전용 그래프 DB를 검토한다.

### GraphRAG 판단

키워드 검색과 공유 엔티티 기반 그래프 검색을 같은 기대 사건으로 비교하는 실험기를 제공한다. 표현이 달라도 IP·파일·프로세스가 겹치는 사건은 그래프 검색이 찾을 수 있다. 현재 MVP는 근거 사건 ID 반환이면 충분하므로 생성형 LLM을 추가하지 않고 그래프 검색만 사용한다. 실제 평가에서 그래프 검색의 recall 개선이 없으면 키워드 검색을 유지하고 증거 데이터를 먼저 보강한다.
# Windows 확장 수집·파일 검사·위협 콘텐츠

`WindowsTelemetryCollector`는 Security, PowerShell, Defender, DNS, Task Scheduler,
System, Sysmon, USB, WinRM 채널을 공통 이벤트로 정규화하며 소스별 손실·지연·정상
시각을 보고한다. `AdvancedFileScanner`는 캐시, 예외 정책, 압축·PE·Office 분석을
기존 YARA·Defender 검사 위에 결합한다. `ThreatIntelStore`와 콘텐츠 관리 계층은
외부 전송 없이 IOC/STIX/TAXII, GeoIP/ASN, Sigma 후보와 공식 콘텐츠를 검증한다.
